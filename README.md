# Практическая работа № 4 — оценка качества ML-модели

**Дисциплина:** «Технологии и инструментарий машинного обучения»  
**Тема:** «Разработка системы анализа риска сердечных заболеваний методами машинного обучения»  
**Практическая № 4:** «Оценка качества моделей, интерпретируемость и валидация результатов».

> Важное уточнение: в ZIP вложен оригинальный отчёт, который был предоставлен
> в Word. Python-код подготовки метрик и проверок создан **заново по описанию**
> в отчёте и совместим с кодом признаков ПР № 3. Это не восстановленный
> оригинальный экспериментальный скрипт. Точные значения из отчёта пока
> **не подтверждены повторным запуском**, потому что модель и исходные
> CSV-файлы не были приложены.

## Что требуется из предыдущих практических

Модель **не переобучается на тестовых данных**. Перед запуском нужно
перенести в эту папку **свои исходные файлы из ПР № 2 и № 3**:

| Куда положить | Что это |
|---|---|
| `models/model_v1.joblib` | сохранённый Pipeline модели v1 из ПР № 3 |
| `data/train.csv` | 65 обучающих записей |
| `data/test.csv` | 17 отложенных тестовых записей |
| `data/batch_01.csv` … `data/batch_04.csv` | четыре порции по 14 обследований |

Если модель хранится в проекте ПР №3 как `results_pr3/model_v1.joblib`,
можно скопировать оттуда. Для восстановления файла `.joblib` используется
модуль `features.py` из того же проекта. Запускайте код только с собственной
доверенной моделью: `joblib.load` применяет небезопасный для чужих файлов
механизм десериализации pickle.

Не включайте персональные медицинские данные в открытый репозиторий без
разрешения. По умолчанию `.gitignore` исключает CSV/XLSX и `.joblib`.

## Установка и запуск

Требуется Python 3.10+; желательно отдельная виртуальная среда:

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS/Linux:
# source .venv/bin/activate
python -m pip install -r requirements.txt
```

Проверка функций контроля данных:

```bash
python -m pytest -q
```

Оценка сохранённой модели без новых порций:

```bash
python evaluate_pr4.py --train data/train.csv --test data/test.csv --model models/model_v1.joblib
```

С четырьмя порциями:

```bash
python evaluate_pr4.py --train data/train.csv --test data/test.csv --model models/model_v1.joblib --batches data/batch_01.csv data/batch_02.csv data/batch_03.csv data/batch_04.csv
```

В `results/` создаются `metrics.json`, `threshold_grid.csv`, изображения
матрицы ошибок, ROC- и PR-кривые, анализ важности признаков, частичные
зависимости, а при наличии порций — `batch_metrics.csv` и график PSI.

**Сверка с отчётом.** В отчёте для сохранённой v1 указаны тестовый ROC-AUC
0,708 и порог 0,35. Это сведения *из отчёта*, не результат запуска данного
архива. Если после передачи точных исходных файлов расчёты отличаются,
проверьте: идентичность train/test, порядок порций, версию модели и
особенности алгоритма из ПР № 3. Не подгоняйте код под числа отчёта.

## Как разместить на GitHub

1. Создайте новый репозиторий (например, `heart-disease-pr4`) **или**
   откройте существующий репозиторий семестрового проекта.
2. Распакуйте ZIP и загрузите **содержимое** `pr4_GitHub` через
   `Add file → Upload files`; если используете существующий репозиторий,
   можно загрузить папку целиком под именем `pr4`.
3. Зафиксируйте коммит `Add practical work 4`.
4. Если требуется методичкой, создайте тег `pr4` на коммите с готовой
   практической № 4. Убедитесь, что тег действительно появился.
5. В отчёт добавьте ссылку на репозиторий и **фактически созданный** тег.
